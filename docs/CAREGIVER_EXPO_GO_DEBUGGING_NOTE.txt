APP ERROR — SIMPLE EXPLANATION
The app's "access denied" page was behind the same access check that sends users to that page. When a session entered a denied state, the app kept sending the user back to the same page. This endless navigation caused the red "Maximum update depth exceeded" screen. The page was moved outside that protected area, so it can display normally. The initial reason the session became denied was not conclusively identified; signing out and logging in with the seeded caregiver account worked.

APP ERROR — TECHNICAL EXPLANATION
Expo Router applies apps/mobile/app/(app)/_layout.tsx to every route in the (app) group. In the access_denied and deactivated branches, that layout returned <Redirect href="/(app)/access-denied" />. The destination was apps/mobile/app/(app)/access-denied.tsx, so navigating to it remounted the same parent guard, which issued the same redirect again. Repeated React Navigation store updates surfaced as "Maximum update depth exceeded" in expo-router/useSyncState and ReactFabric. The stack pointed at router internals, but the cause was the app's self-referential route topology.

Fix: move the screen to apps/mobile/app/access-denied.tsx, outside the (app) guard; update redirect targets to /access-denied. When the denied session is cleared, that page now redirects to /(auth)/login. An empty login form previously called signIn() with no credentials, which invoked an unconfigured OIDC redirect URI; it now asks for an email instead.

VERIFICATION AND REPEAT-ISSUE CLUES
On a Samsung SM-A035F using Expo Go, the seeded caregiver account logged in, displayed linked patient Sita Sharma, and opened Home, Record, and You without the render error. Local checks passed: TypeScript, Android export, 437 unit tests, 184 component tests, and ESLint with zero errors (63 warnings). If this error returns, check whether any access-denied destination is again nested beneath a layout that redirects denied users to that same destination. Also check the first app-owned frame in the Metro log and the auth state; do not assume expo-router itself is the cause from the ReactFabric stack alone.
